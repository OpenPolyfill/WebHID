## Notes

- **`B4` (activation)**: Ordinary page calls to `requestDevice()` require transient activation. DevTools console invocation follows Chromium-compatible behavior; `allowActivationlessRequestDevice` is an explicit opt-in override (off by default). The chooser still requires user selection.
- **`B13`**: Devices granted together are tracked as a permission group. `permissionGroupStates()` resolves the related page-device states and `forgetDevice()` immediately marks the group as `forgetting`, aborts its pending report operations, then requests revocation through `unpairDevice`. The background grant-group revocation path closes and invalidates the corresponding daemon authority. See the group lifecycle assertions in `tests/conformance/e2e/e2e.spec.ts`.
- **`B33`**: Header policy is captured in `background/webrequest.js` and keyed to browser-owned frame/document identity. The exact child bridge resolves delegation against its real parent endpoint; the parent checks the matching iframe/frame element using browser runtime frame/document IDs and evaluates the `hid` allow directive. The default remains same-origin (`self`); cross-origin children fail closed without valid delegation.
- **`I5b`**: `hidInstance` is a module-level singleton in `content/main/index.js`; the `navigator.hid` getter returns it on every access, satisfying `[SameObject]`.
- **`B59` / `B60` / `B61` (worker context)**: `workerPolyfillEnabled` is off by default. When enabled, the polyfill exposes `navigator.hid`, WebHID interfaces and `getDevices()` inside page-created Dedicated Workers. `requestDevice()` remains Window-only; non-Window behavior is compliant when the method is absent under `[Exposed=Window]` or rejects with `NotSupportedError` under §6.2. The current implementation omits the method in Workers. No functional worker data plane is created by this feature. Browser-test evidence is in `tests/conformance/browser/worker.spec.ts`.
- **`I9` / `B62` / `B63` (ServiceWorker context)**: The WebHID draft explicitly says a user agent may choose to conditionally expose `hid` when the relevant global is `ServiceWorkerGlobalScope`. This polyfill supports Dedicated Workers but does not inject into ServiceWorkerGlobalScope. `requestDevice()` is `[Exposed=Window]` and remains page-only. These are conditional, non-scored capabilities, not unresolved mandatory failures.
- **Worker polyfill wiring**: when `workerPolyfillEnabled` is on, `background/webrequest.js` serves the bundle listed by `addon/js/utils/bundle-files.js` into page-created worker scripts through `webRequest.filterResponseData`. The bundle contains bootstrap, logger, http, settings, device-filters, webtransport, wire-format, and `content/main/index.js`. The patched Worker constructor relays the worker's bridge port.
